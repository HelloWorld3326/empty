# Ontology 演练场

一个可交互的单页 Demo，用来直观感受 Palantir Ontology 的两半：

- **本体建模** —— 从零定义对象类型、链接类型、操作类型
- **实例运行** —— 用你定义出来的东西去操作真实数据

不复刻 Foundry 的复杂功能，只把这套设计的骨架跑通。数据在内存里，刷新即重置。

```bash
git clone https://github.com/HelloWorld3326/empty.git
cd empty
open index.html      # 或者直接把 index.html 拖进浏览器
```

零依赖、零构建：一个自包含的 `index.html`。

## 为什么分成两个模式

Ontology 里「定义类型」和「操作实例」本来就是两件事（Ontology Manager 对 Object Explorer）。
只看已经建好的本体，会漏掉最关键的一半：这些类型是怎么被定出来的，以及改动类型时数据会发生什么。

顶部切换两个模式，概念说明和图谱都会跟着换：

| | 本体建模 | 实例运行 |
|---|---|---|
| 图谱画的是 | **类型**之间的关系 | **实例**之间的关系 |
| 你在操作 | 对象类型 / 链接类型 / 操作类型 | 具体的对象、链接 |
| 右栏是 | 变更影响 + 本体变更记录 | 操作执行器 + 写入日志 |

配色带语义：**冷色 = 类型与数据**，**琥珀 = 写入**（无论写的是 schema 还是实例）。

## 本体建模能做什么

**对象类型** —— 改中文名、主键前缀、标题属性、配色；增删属性并选数据类型
（文本 / 整数 / 金额 / 枚举 / 日期 / 时间 / 布尔）。
新增属性会**立刻给所有已有实例补上默认值**，改属性类型会迁移已有的值 —— 右栏实时告诉你影响了多少条数据。

**链接类型** —— 改两端类型、基数、正反双向的名字。
基数不只是标注：重数为 `1` 的一端，建立新链接时会自动断开旧的那条，你会在编辑预览里看到这条 `UNLINK`。

**操作类型** —— 这是建模里最有内容的一块，用表单配出一个完整的 Action：

- **参数**：对象引用（限定类型）/ 数字 / 文本 / 枚举
- **校验规则**：属性比较、链接数量、链接存在性；每条规则下面实时生成一句人话
- **写入编辑**：新建对象、修改属性（设为 / 增加 / 减少 / 乘以）、建立或断开链接、删除对象

规则和编辑的**目标**不只是参数本身，还可以是「某参数沿某条链接走一步」得到的对象 ——
一个操作因此能顺着图改到好几个对象。

还有两个脚手架：从对象类型一键生成「新建 XXX」操作，从链接类型一键生成「关联」操作。
生成出来的就是普通的操作类型，可以接着改。

**删除**任何类型前，右栏会先算清楚代价：牵动多少实例、多少链接、多少其它类型。

## 示例本体

场景是一条咖啡器材供应链。5 个对象类型：`Customer` `Order` `Product` `Warehouse` `Shipment`。

5 个链接类型，四种基数各有覆盖：

| 链接类型 | 关系 | 基数 |
|---|---|---|
| `placed` | Customer → Order | 1 : N |
| `contains` | Order → Product | N : N |
| `fulfilledBy` | Order → Shipment | 1 : 1 |
| `shipsFrom` | Shipment → Warehouse | N : 1 |
| `stockedAt` | Product → Warehouse | N : N |

6 个操作类型，每个演示 Action 的一个不同侧面：

| 操作 | 演示的点 |
|---|---|
| `createOrder` 下单 | 一个 Action 同时创建对象、建两条链接、改第三个对象的库存 |
| `approveOrder` 审核订单 | 最小 Action：只改一个属性，状态机由校验规则守住 |
| `shipOrder` 发货 | 校验规则沿着 `订单 → 商品 → 存放仓库` 走图，确认仓库真的有货 |
| `deliverShipment` 确认送达 | 参数只给运单，编辑顺着 `fulfilledBy` 的**反向**链接找到订单，一起改掉 |
| `cancelOrder` 取消订单 | 撤销类写入：沿链接找回商品，把库存还回去 |
| `restockProduct` 补货入仓 | 条件编辑：链接不存在时才建 |

这 6 个操作和你自己新建的操作**格式完全相同** —— 都是声明式数据，都能在建模模式里打开改。

## 可以试试

**从零走一遍**：点「从零开始」清空本体 → 新建对象类型、加几个属性 → 用脚手架生成「新建 XXX」
操作 → 切到实例运行执行它 → 你定义的类型长出了第一个实例。

**改一个活着的本体**：给 `Order` 加一个「折扣」属性，看右栏说 4 个已有订单被补上了默认值；
或者把 `stockedAt` 的基数从 `N : N` 改成 `N : 1`，再去补货，看编辑预览里多出来的 `UNLINK`。

**运行模式里**：点图谱节点看对象详情；点「关联对象」沿链接在图里走（这就是 Ontology 的查询，
不写 JOIN）；改参数看校验规则实时变红变绿；故意让校验失败，提交按钮会被锁住；
应用一次操作后撤销它。

**本体规格 JSON**：整份本体（类型 + 实例）都可以导出、编辑、贴回去生效 ——
本体说到底是一份可序列化的声明式规格。

## 实现说明

| 部分 | 位置（`index.html` 内的分节注释） |
|---|---|
| 默认本体 schema + 种子实例 | §2 |
| **Action 解释器**（Target / Ref / Rule / Edit 求值） | §4 |
| 编辑引擎（应用 + 求逆） | §5 |
| 力导向图谱（类型图与实例图共用） | §7 |
| 建模编辑器（三种类型） | §10 |
| schema 变更与数据迁移 | §11 |

关键设计：**Action 是数据，不是代码**。参数、校验规则、写入编辑都是可序列化的结构，
由 §4 的解释器求值。正因为如此，内置操作和你在界面上配出来的操作才是同一种东西。

编辑用五种原语表达：`create` / `modify` / `delete` / `link` / `unlink`。
`applyEdits()` 一边应用一边算出逆操作序列，撤销就是把逆序列再喂回同一个函数。

界面适配浅色与深色主题，跟随系统设置。
