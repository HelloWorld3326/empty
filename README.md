# Ontology 演练场

一个可交互的单页 Demo，用来直观感受 Palantir Ontology 里最基本的三件东西：
**Object（对象）· Link（链接）· Action（操作）**。

不复刻 Foundry 的复杂功能，只把这套设计的骨架跑通 —— 数据是内存里的，刷新即重置。

```bash
git clone https://github.com/HelloWorld3326/empty.git
cd empty
open index.html      # 或者直接把 index.html 拖进浏览器
```

零依赖、零构建：一个自包含的 `index.html`。

## 演示的是什么

场景是一条小咖啡器材供应链：客户下单 → 审核 → 从仓库发货 → 送达。

### 三个基本件

| | 含义 | 在界面上 |
|---|---|---|
| **Object** | 现实世界的实体，属于某个*对象类型*，有固定属性表和唯一主键 | 图谱里的节点、下方的属性面板 |
| **Link** | 对象之间的关系，有类型、有方向、有基数 | 节点之间的连线、详情里的「关联对象」 |
| **Action** | 唯一的写入口：参数 → 校验 → 生成一组编辑 → 原子写回 | 右栏的操作执行器 |

配色本身带语义：**冷色 = 读**（对象与链接），**琥珀 = 写**（Action 产生的编辑）。

### 本体模型

5 个对象类型：`Customer` `Order` `Product` `Warehouse` `Shipment`

5 个链接类型，四种基数各有覆盖：

| 链接类型 | 关系 | 基数 |
|---|---|---|
| `placed` | Customer → Order | 1 : N |
| `contains` | Order → Product | N : N |
| `fulfilledBy` | Order → Shipment | 1 : 1 |
| `shipsFrom` | Shipment → Warehouse | N : 1 |
| `stockedAt` | Product → Warehouse | N : N |

6 个操作类型，每个都在演示 Action 的一个不同侧面：

| 操作 | 演示的点 |
|---|---|
| `createOrder` 下单 | 一个 Action 同时创建对象、建立两条链接、修改第三个对象的库存 |
| `approveOrder` 审核订单 | 最小 Action：只改一个属性，状态机由校验规则守住 |
| `shipOrder` 发货 | 校验规则沿着 `订单 → 商品 → 存放仓库` 走图，确认仓库真的有货 |
| `deliverShipment` 确认送达 | 参数只给运单，编辑顺着 `fulfilledBy` 的**反向**链接找到订单，一起改掉 |
| `cancelOrder` 取消订单 | 撤销类写入：改状态之余沿链接找回商品，把库存还回去 |
| `restockProduct` 补货入仓 | 条件编辑：链接不存在时才顺手建一条 |

## 可以试试

- **点图谱节点**看对象详情；节点可拖拽，边上会标出链接类型名和方向。
- **点详情里的关联对象**，沿着链接在图里走 —— 这就是 Ontology 的「查询」，不写 JOIN。
- **改右栏的参数**，看校验规则实时变红变绿，以及「编辑预览」里将要写入的东西怎么跟着变。
- **故意让校验失败**（比如审核一个已审核的订单、发货时选一个没货的仓库），提交按钮会被锁住。
- **应用一次操作**，看新对象在图里以琥珀色高亮出现，写入日志记下它产生的每一条编辑。
- **撤销**最近一次操作 —— 每组编辑在应用时都算好了逆操作。
- **点左栏的类型**筛选图谱，只看某一类对象或某一种链接。

## 实现说明

| 部分 | 位置 |
|---|---|
| 本体定义（对象类型 / 链接类型） | `index.html` 第 1 节 |
| 实例种子数据 | 第 2 节 `seedWorld()` |
| Action 定义（参数 / 校验 / 编辑） | 第 3 节 `ACTIONS` |
| 编辑引擎（应用 + 求逆） | 第 4 节 `applyEdits()` |
| 力导向图谱（canvas） | 第 7 节 |

编辑用五种原语表达：`create` / `modify` / `delete` / `link` / `unlink`。
`applyEdits()` 一边应用一边算出逆操作序列，撤销就是把逆序列再喂回同一个函数。

界面适配浅色与深色主题，跟随系统设置。
