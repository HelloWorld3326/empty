# 一期启动手册 · 第一周逐日操作

> 配套文档：`一期技术方案与任务拆解.md`（决策、架构、任务表）
> 配套文件：`starter/`（可直接复制执行的 docker-compose、.env、CLAUDE.md 模板、任务卡模板）

---

## 先纠正一个思路

很多人会这样规划：**部署数据库 → 建表 → 写后端 → 写前端**。

这个顺序不能说错，但它是**串行**的——第一步没做完，后面四个人只能等。五个人的项目按这个节奏走，第一周实际只有一个人在产出。

正确的理解是：

> **第一周不写任何业务代码，写的是「让五个人能同时干活的地基」。**

这个地基包含三样东西，缺一样就会有人卡住：

| 地基 | 谁被它卡住 | 铺好要多久 |
|---|---|---|
| 能跑起来的数据库 + 建好的表 | 两个后端、算法 | **半天** |
| 写死的接口定义（OpenAPI） | 所有人 | 2 天 |
| 基于接口定义的假数据服务（mock） | 前端 | 1 天 |

关键在于：**地基里最贵的不是数据库，是接口定义**。数据库半天就起来了，但"这个接口叫什么、传什么、返回什么"如果不先说死，五个人就会各写各的，第三周拼起来的时候全是对不上的字段。

所以第一周的目标不是"写出功能"，而是**"让第二周开始，五个人可以完全不互相等待地并行工作"**。

---

## Day 0 · 半天 · 1 个人（BE1）

这是唯一必须串行的半天。一个人做完，其他人 clone 下来就能跑。

### 1. 建仓库，定目录

```bash
mkdir agent-platform && cd agent-platform
git init
mkdir -p contracts/mock backend agent-runtime frontend deploy var/attachments
```

目录含义：

```
contracts/     契约：建表语句、接口定义、SSE 协议  ← 唯一真源
backend/       FastAPI 业务后端
agent-runtime/ Agent 执行内核（独立包）
frontend/      Vue3 前端
deploy/        docker-compose、部署脚本
```

### 2. 拉起数据库和 Redis

把 `docs/starter/docker-compose.yml` 复制到 `deploy/`，然后：

```bash
cd deploy && docker compose up -d
docker compose ps          # 两个容器都是 healthy 就对了
```

这一步就是你说的"部署 PG 和 Redis"——用 Docker 的话是**一条命令、五分钟**的事，不需要专门排期。

> 注意 compose 文件里挂载了 `contracts/schema.sql`：容器**首次启动**会自动执行它建表。
> 现在这个文件还不存在，所以先起来是空库，Day 2 写完 DDL 后执行
> `docker compose down -v && docker compose up -d` 重建即可（`-v` 会删掉数据卷）。

### 3. 环境变量

复制 `docs/starter/.env.example` 到根目录，各人改名为 `.env` 填自己的值。
**`.env` 必须写进 `.gitignore`，永远不提交。**

### 4. 项目约定

把 `docs/starter/CLAUDE.md.template` 复制成根目录的 `CLAUDE.md`（用 Codex 的人再复制一份 `AGENTS.md`）。
这份文件 AI 会自动读，它决定了 AI 生成的代码符不符合你们的规矩。

### 5. 推第一个提交

```bash
git add -A && git commit -m "chore: 项目骨架与本地开发环境"
git push -u origin main
```

**Day 0 验收**：任何一个组员执行 `git clone` → `cd deploy && docker compose up -d`，
两个容器 healthy。到此为止，基础设施这件事就结束了，整个一期不用再管。

## Day 1 · 全员开工

### 上午：Kickoff 会（1 小时，必须开）

不是走过场。要当场对齐三件事：

1. **过一遍决策台账**（技术方案文档第 1 节的 18 条）。逐条念，谁有异议现在提。
   会后这 18 条就是不可推翻的前提，谁想改走变更流程。
2. **讲清楚"垂直切片"分工法**：一个人从表到接口到页面把一个切片做完，
   不要按层分工。当场把任务表（第 7 节 S0–S24）分掉。
3. **当场认领三个外部依赖的 owner**：
   - 谁去盘点内网有没有现成的 MCP Server（风险 R3）
   - 谁去要内网知识库的接口文档（风险 R1）
   - 谁去申请 +1 前端（风险 R2）

### 下午：五个人分头开工

| 人 | 今天做什么 | 今天结束时应该有什么 |
|---|---|---|
| **BE1** | 写 `contracts/schema.sql` 的前半部分：身份权限 4 张表 + 智能体域 5 张表 | 9 张表的 DDL，能在本地库跑通 |
| **BE2** | 写 `contracts/openapi.yaml` 骨架：把 65 个接口的**路径和方法**先列全，请求响应体先留空 | 一份能被工具解析的 yaml，路径全对 |
| **AL** | 写一个几十行的脚本，直接调百炼的 OpenAI 兼容端点，验证 function calling 能用 | 终端里能看到模型返回 `tool_calls` |
| **FE1** | `pnpm create vite` 起 Vue3 + TS 项目，装 Pinia、Ant Design Vue、配好路由和布局壳子 | 浏览器能打开，左侧导航和空白页面在 |
| **FE2** | 组件基建：表格封装（带分页/搜索/选择列）、弹窗封装、表单封装 | 三个能用假数据渲染出来的基础组件 |

**注意 AL 今天这个脚本非常重要**，它是整个项目风险最高的一次验证：
如果百炼的 function calling 跟预期不一样，整个 agent 运行时的做法要改，
现在发现只损失一天，第三周发现就要命了。

## Day 2 · 表建起来、接口定义补肉

| 人 | 做什么 |
|---|---|
| **BE1** | 补完 `schema.sql` 剩下的资源域 5 张表 + 会话运行域 7 张表；写 `seed.sql`（角色权限初始数据、默认管理员账号、默认组）；**跑通建库**：`docker compose down -v && up -d`，20 张表全部建好 |
| **BE2** | 给 `openapi.yaml` 的每个接口补请求体和响应体的 schema，先补 agents / resources 两组 |
| **AL** | 把昨天的脚本扩展成"能流式输出"：模型的回答一个字一个字打印出来 |
| **FE1** | 接入请求层（axios 封装、错误处理、loading 态），先连一个写死的 JSON 文件跑通 |
| **FE2** | 继续组件基建 + 开始做流式渲染组件的原型（先用 `setInterval` 假装有字在流进来） |

**Day 2 验收**：
```bash
docker compose exec postgres psql -U agent -d agent_platform -c "\dt"
# 应该看到 20 张表
docker compose exec postgres psql -U agent -d agent_platform -c "select * from sys_user;"
# 应该看到 seed 进去的默认管理员
```

这就是你说的"在数据库执行 DDL 把表建好"——它确实要早做，因为**表结构是所有人的共同语言**：
后端照着它写查询、前端照着它理解字段含义、AI 照着它生成代码。但它只值 1.5 天，不是一周。

## Day 3 · SSE 协议定稿 + 假服务上线（最关键的一天）

这一天决定了前端能不能提前两周开工。

| 人 | 做什么 |
|---|---|
| **AL + BE2 + FE2 三人当天上午一起开 1 小时** | 定稿 `contracts/sse-protocol.md`：9 类事件的字段全部写死，并写一段"一次完整运行"的示例事件流 |
| **BE2** | 用 FastAPI 写一个**假的 SSE 服务**：不接大模型，就按示例事件流定时往外吐假数据（比如每 200ms 吐一个 `message.delta`）。这个服务几十行代码 |
| **AL** | 开始搭 `agent-runtime` 的骨架，把昨天的流式脚本改造成能发出这 9 类事件 |
| **FE2** | **把流式渲染组件接到假 SSE 服务上**——浏览器里应该能看到思考过程实时展开、字一个个蹦出来、引用条数往上加 |
| **BE1** | 补完 `openapi.yaml` 剩下的 conversations / runs / records 三组 |
| **FE1** | 跑通 mock server：用 Prism 或 msw 从 `openapi.yaml` 自动生成假接口，前端所有列表页都能拉到假数据 |

**Day 3 验收（这是第一周最重要的一次验收）**：
前端在浏览器里，**在后端一行业务代码都没写的情况下**，
能看到一个假的智能体在流式回答问题，思考过程在展开，引用来源在累加。

到这一刻，前端就彻底解绑了——接下来两周它不需要等任何人。

## Day 4 · 类型生成 + CI + 错误码

| 人 | 做什么 |
|---|---|
| **BE1** | 写 `contracts/errors.md` 统一错误码表；配 CI（跑 lint + 测试 + 校验 openapi.yaml 合法） |
| **BE2** | 后端接入 spec：从 `openapi.yaml` 生成 Pydantic model，路由骨架全部建好（函数体先 `raise NotImplementedError`） |
| **AL** | `agent-runtime` 骨架 + 单元测试框架，能跑通"输入一句话，输出 9 类事件" |
| **FE1** | 前端接入 spec：从 `openapi.yaml` 生成 TS 类型和 API 客户端到 `src/api/`，全部页面改用生成的类型 |
| **FE2** | 继续组件库，把 Day 3 的流式组件收拾成可复用的 |

**为什么类型生成这么重要**：这是防 AI 幻觉的核心护栏。
AI 写代码最常见的错就是**字段名编错**——后端叫 `agentId`，前端 AI 写成 `agent_id`，
运行时才发现是 `undefined`。用生成的类型之后，编译期就红了，根本提交不上去。

## 第二周之后：怎么用 AI 干活

第一周之后节奏就固定了，每个人循环做这四件事：

**1. 领一张切片任务卡** —— 上面写清楚四件事：切片范围、已定的契约、验收标准、不许动什么。

**2. 整段贴给 AI，让它做完这个切片** —— 从建 service、写路由、写页面到写测试。
因为契约已经写死了，AI 不会编字段名；因为划了边界，AI 不会去改别人的文件。

**3. 自己 review** —— 重点看四项：权限有没有漏（能不能越权读别人的资源）、
有没有 N+1 查询、外部调用有没有超时处理、测试测的是行为还是实现。
**看不懂的代码不许合。**

**4. 跑通验收标准，提 PR** —— 验收标准里的每一条都要真的点一遍，包括异常情况。

> **AI 提速的边界要有心理准备**：AI 让"敲代码"快 2.5–3 倍，
> 但"想清楚要什么、跟别人对齐、拿到内网权限、验收异常路径"这些一点没变快。
> 所以任务卡写得越清楚，AI 的产出越高——**你花在写任务卡上的 20 分钟，
> 能省 AI 两小时的返工。**

## 每周固定动作

| 时间 | 动作 | 时长 |
|---|---|---|
| 每天早上 | 站会：昨天做完什么、今天做什么、被谁卡住 | 10 分钟 |
| 每周一 | 契约对齐会：过一遍这周 `contracts/` 的改动，有没有人的代码需要跟着改 | 30 分钟 |
| 每周五 | 里程碑验收：按周计划里的判定标准逐条演示 | 30 分钟 |

**里程碑判定标准（技术方案第 9 节）**：
- W2 末 **M1**：创建 agent → 即时测试 → 看到流式回答（工具用 mock）
- W3 末 **M2**：agent 能真调 MCP 工具、真查知识库；发布 / 上下架闭环
- W4 末 **M3**：功能完整，happy path 全通
- W5 末 **M4**：可交给业务专家试用

**M1 是最关键的一道闸**。如果 W2 末这条最短链路没通，不要继续往下堆功能——
先停下来查为什么，因为后面所有东西都挂在这条链路上。

> 每周五按里程碑验收。
