# 实施步骤（通俗版）

按顺序做，每一步都有明确的「做完的标志」。总工期预计 **2～4 周**（含知识库整理和测试）。

---

## 第 1 步：准备（0.5 天）

- 一台服务器：4 核 8G、50G 磁盘起步，能访问外网（要调云端大模型）。
- 申请一个大模型 API Key：DeepSeek / 通义千问 / OpenAI 任选，先充一点钱测试。
- 另外准备一个 Embedding（向量）模型的 Key，知识库必须用它。
- 让业务同事整理客服资料：FAQ、产品手册、退换货政策、话术。**一问一答的 Excel/Word 效果最好。**

✅ 做完的标志：服务器能 ssh 上去，模型 Key 用 curl 能调通。

---

## 第 2 步：装 MaxKB（0.5 小时）

```bash
docker run -d --name=maxkb --restart=always -p 8080:8080 \
  -v ~/.maxkb:/opt/maxkb 1panel/maxkb
```

浏览器打开 `http://服务器IP:8080`，默认账号 `admin / MaxKB@123..`，**第一件事改密码**。

✅ 做完的标志：能登录 MaxKB 后台。

---

## 第 3 步：接大模型（0.5 小时）

MaxKB 后台 → 系统设置 → 模型管理 → 添加模型：

1. 加一个**大语言模型**（填你的 DeepSeek/通义/OpenAI Key）；
2. 再加一个 **Embedding 向量模型**（知识库必须）。

✅ 做完的标志：模型列表里两个模型都显示「可用」。

---

## 第 4 步：建知识库（1～3 天，取决于资料量）

MaxKB → 知识库 → 新建 → 上传资料 → 选分段规则（FAQ 类按「问答分段」）→ 向量化。

然后用「**命中测试**」功能，输入 20～30 个真实客户问过的问题，看召回的段落对不对。

> ⚠️ 这一步的质量决定最终效果的 80%。召回不准，换什么模型都没用。
> 不准就回去调分段方式、补充资料、给段落加标题。

✅ 做完的标志：常见问题的命中率目测 80% 以上。

---

## 第 5 步：建客服智能体（0.5 天）

MaxKB → 应用/智能体 → 新建 → 关联刚才的知识库 → 配置：

- **角色提示词**参考：
  > 你是 XX 公司的在线客服。只依据知识库内容和工具返回的数据回答，
  > 不确定或知识库没有的内容，明确告知客户并引导转人工，绝对不要编造。
  > 回答简洁友好，不超过 200 字。
- 开场白、常见问题快捷入口；
- 打开「显示知识来源」，方便排查；
- 设置无答案时的兜底回复。

✅ 做完的标志：在 MaxKB 的调试窗口里问 10 个问题，答得像个客服。

---

## 第 6 步：部署自研的两个服务（0.5 天）

本仓库提供了两个服务：

| 服务 | 作用 | 端口 |
|---|---|---|
| `services/tool-api` | 业务工具 API，给 MaxKB 工作流查客户数据 | 8100（**只对内网**） |
| `services/chat-gateway` | 对话网关，客户360 前端唯一对接的服务 | 8200 |

```bash
cp services/tool-api/.env.example     services/tool-api/.env
cp services/chat-gateway/.env.example services/chat-gateway/.env
# 编辑两个 .env，重点填 MAXKB_API_KEY 和 TOOL_API_SERVICE_KEY（两边必须一致）

docker compose up -d --build
```

先用内置的 mock 数据跑通链路，再切真实数据源：

```bash
export TOOL_API_SERVICE_KEY=你设置的值
./scripts/smoke_test.sh      # 6 项检查全过才算通
```

✅ 做完的标志：冒烟测试输出「全部通过 ✅」。

---

## 第 7 步：接上你们的真实数据（1～2 天）

编辑 `services/tool-api/.env`，二选一：

**方式 A · 直连数据库**（你们有库权限）
```
TOOL_DATA_SOURCE=db
TOOL_DB_DSN=postgresql+psycopg://用户:密码@主机:5432/库名
```
然后按你们的表结构改 `services/tool-api/app/repository.py` 里的 SQL。
**改的时候务必保留 `WHERE customer_id = :cid` 这个条件**，这是防越权的最后一道防线。
建议给这个服务单独开一个**只读数据库账号**。

**方式 B · 转调已有接口**（推荐，复用现成的权限和风控）
```
TOOL_DATA_SOURCE=http
TOOL_UPSTREAM_BASE_URL=http://customer360.internal/api
TOOL_UPSTREAM_TOKEN=服务间调用的令牌
```
按你们接口的实际路径调整 `repository.py` 里的 `_get_upstream` 调用即可。

✅ 做完的标志：`curl` 能查出一个真实客户的真实订单，且手机号已脱敏。

---

## 第 8 步：在 MaxKB 里把工具挂上去（0.5 天）

见 [03-MaxKB配置指南.md](./03-MaxKB配置指南.md)，核心是把应用切成**工作流**模式，
加 HTTP 请求节点去调 `tool-api`。

✅ 做完的标志：在 MaxKB 调试窗口问「我的订单状态」，能返回真实数据。

---

## 第 9 步：客户360 前端接入（1～2 天）

参考 `web/demo/index.html`，你们前端只需要做三件事：

1. `POST /api/chat/sessions` 拿 `conversation_id`（带上客户360 的登录态）；
2. `POST /api/chat/messages` 流式读取回答，做打字机效果；
3. `POST /api/chat/handoff` 转人工。

**上线前必须把 `AUTH_MODE` 从 `debug` 改成 `jwt` 或 `introspect`**，否则任何人改个请求头就能冒充别的客户。

✅ 做完的标志：在客户360 页面上，用两个不同账号登录，各自只能查到自己的数据。

---

## 第 10 步：灰度上线与运营（持续）

- 先放 5% 流量，或先只对某一类问题启用；
- 每天看 MaxKB 的对话日志和点踩记录；
- **每周把答错的问题补进知识库**——客服 Agent 是养出来的，不是一次配好的；
- 关注三个指标：解决率、转人工率、平均响应时长。

---

## 上线检查清单

- [ ] `AUTH_MODE` 不是 `debug`
- [ ] MaxKB 后台密码已改，且后台不暴露公网
- [ ] `tool-api` 只监听内网，未映射到公网
- [ ] `TOOL_API_SERVICE_KEY` 是随机长字符串，两个服务一致
- [ ] `TOOL_MASK_PII=true`
- [ ] 数据库账号是只读的（走方式 A 时）
- [ ] `CORS_ORIGINS` 限定为客户360 的域名
- [ ] 内存版的会话表/限流器已换成 Redis（多副本部署时）
- [ ] 全链路 HTTPS
- [ ] 审计日志有落盘且有备份
- [ ] `scripts/smoke_test.sh` 全绿
