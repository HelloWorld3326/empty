# MaxKB 后台配置指南

> 不同版本（v1 / v2）的菜单名称和接口路径略有差异，本文按 v2 描述。
> 涉及接口路径的地方，请以你部署那个版本**自带的 API 文档**为准，
> 代码里已把路径做成环境变量（见 `services/chat-gateway/.env.example`），改配置即可，不用改代码。

## 一、创建 API Key（给网关用）

进入你的智能体 → 概览 → **API Key** → 创建。

- 这个 Key 填到 `services/chat-gateway/.env` 的 `MAXKB_API_KEY`；
- **绝对不要**出现在前端代码里；
- 建议为不同接入方各建一个 Key，方便单独禁用和排查。

## 二、「嵌入第三方」怎么用（可选）

同样在智能体概览页，点 **嵌入第三方**，可以复制三种代码：

| 模式 | 形态 | 适合 |
|---|---|---|
| 全屏模式 | iframe 整页嵌入 | 独立的「在线客服」页面 |
| 浮窗模式 | 一段 JS，右下角小图标 | 挂在客户360 各个页面上 |
| 移动端模式 | 适配手机 | App 内嵌 H5 |

同时记得配置：**域名白名单（防盗链）**、**提问频率限制**、**是否展示知识来源**。

> ⚠️ 再强调一次：这种方式**认不出登录的是哪个客户**，只能做纯知识问答。
> 要查「我的订单」，走 `chat-gateway` 的方案。

## 三、把工具挂进工作流（关键步骤）

把应用切换成**工作流**模式，典型编排如下：

```
开始
 └─> 问题分类（判断意图）
      ├─ 一般咨询 ──> 知识库检索 ──> AI 对话 ──> 结束
      └─ 查我的数据 ──> HTTP 请求（调 tool-api）──> AI 对话（把结果讲成人话）──> 结束
```

### HTTP 请求节点怎么配

以「查我的订单」为例：

| 配置项 | 值 |
|---|---|
| 请求方式 | `GET` |
| 地址 | `http://tool-api:8100/tools/customer/orders`（同 compose 网络内）<br/>或 `http://内网IP:8100/tools/customer/orders` |
| Header 1 | `X-Service-Key` = 你在 `.env` 里设的 `TOOL_API_SERVICE_KEY` |
| Header 2 | `X-Chat-Id` = 当前会话的 chat_id 变量（在 MaxKB 里通常写成 `{{chat_id}}` 之类，具体变量名见你版本的变量选择器） |

**注意这里没有 customer_id 参数** —— 这是刻意的。客户身份由 `X-Chat-Id` 在服务端反查，
模型无法指定要查谁，从根上杜绝了越权。

> 如果你的 MaxKB 版本在工作流里取不到 chat_id，改用第二套方案：
> 在 `.env` 里给两个服务配上相同的 `TOOL_TOKEN_SECRET`，
> 网关会签发一个 30 分钟有效的 `tool_token` 作为对话变量传入，
> HTTP 节点改成带 `X-Tool-Token` 头即可。两套方案代码里都已支持。

### 可用的工具接口

| 接口 | 方法 | 说明 |
|---|---|---|
| `/tools/customer/profile` | GET | 客户基本信息、等级、积分 |
| `/tools/customer/orders?status_filter=&limit=5` | GET | 订单列表 |
| `/tools/customer/orders/{order_no}` | GET | 单个订单详情（含退款进度） |
| `/tools/customer/tickets?limit=5` | GET | 工单列表 |
| `/tools/customer/tickets` | POST | 建工单 / 转人工（唯一的写操作） |

### 后处理节点的提示词参考

HTTP 节点拿到的是 JSON，别直接丢给客户。后面接一个 AI 对话节点：

> 下面是该客户的订单数据（JSON）。请用自然、简洁的中文回答客户的问题，
> 只陈述数据里确实存在的信息，不要推测。如果数据为空，就告诉客户没有查到相关记录，并询问是否需要转人工。
>
> 数据：{{HTTP节点的输出}}
> 客户问题：{{开始节点的问题}}

## 四、调试顺序建议

1. 先在 MaxKB 调试窗口测**纯知识问答**，确认知识库没问题；
2. 再单独用 `curl` 测 `tool-api`（跑 `scripts/smoke_test.sh`）；
3. 再在工作流里测 **HTTP 节点**能不能拿到数据；
4. 最后接前端。

一层层来，出问题时才知道是哪一层坏了。

## 五、常见问题

**Q：HTTP 节点报 403「会话未绑定客户身份」**
A：说明网关没成功登记绑定关系。检查 `chat-gateway` 和 `tool-api` 的 `TOOL_API_SERVICE_KEY` 是否一致，
以及网关能否访问到 `tool-api`。

**Q：HTTP 节点报 401**
A：`X-Service-Key` 头没配或配错了。

**Q：能对话但查数据总说"没查到"**
A：多半是 `X-Chat-Id` 变量名写错，导致传了空值。先在工作流里把这个变量打印出来看看。

**Q：回答很慢**
A：先看是模型慢还是工具慢。工具接口应该在 1 秒内返回；如果是模型慢，考虑换更快的模型或开启流式输出。
