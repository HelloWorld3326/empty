① 集成方式与交付边界（本次只交付后端）

架构：SkillOpt 作为 nexent 的原生功能集成——新增独立后端服务 nexent-skillopt（自带 SkillOpt 引擎依赖的容器，遵循 nexent 多服务模式），鉴权/租户/模型全部走 nexent 现有体系，不自建任何账号或模型配置。

本次后端交付（写进 nexent 仓库）：

  1. 路由层：backend/apps/skillopt_app.py —— APIRouter(prefix="/skillopt")，每个端点 Header(authorization) → get_current_user_id() 解析 (user_id, tenant_id)，遵循 nexent App 层约定（校验入参、委托 service、JSONResponse {message,data}）。
  2. 服务层：backend/services/skillopt_service.py —— 训练子进程管理（Popen scripts/train.py / killpg / 断点续训）、上传校验、模型解析（复用 model_management_db.get_model_by_model_id + model_health_service.check_model_connectivity）、进度解析。
  3. 数据层：backend/database/skillopt_db.py + db_models.py 新增 skillopt_job_t 表（tenant_id/user_id/status/参数快照/out_root/pid…），任务记录持久化、按租户隔离。
  4. 服务入口：backend/skillopt_service_main.py（uvicorn，端口 5016，app_factory.create_app 装配）。
  5. SQL 迁移：建表 + role_permission_t 菜单权限行（权限体系复用 nexent：菜单显隐按角色，接口按 JWT 租户隔离）。
  6. 部署：docker/ 下 nexent-skillopt 镜像（含 SkillOpt 引擎源码与依赖）+ compose 服务定义。

前端待办（不在本次交付，由前端同学按本原型实现）：新页面 frontend/app/[locale]/skill-opt/page.tsx（上方三个 Tab）、SideNavigation 菜单项、zh/en i18n、services/skillOptService.ts、server.js 加 /api/skillopt/* → 5016 转发规则。前端不用管鉴权头（网关自动注入）。

模型配置完全复用 nexent「模型管理」页——本功能不新增任何模型配置界面或接口。

② 接口一览（点上方紫色标签看请求/响应示例；联调以 Swagger 为准）
路径用途调用时机

响应与错误约定（nexent 风格）：成功 = HTTP 200 + {"message":"ok","data":…}； 错误 = HTTPException，body 为 {"detail":"可读原因"}——前端统一 message.error(err.detail)。 关键状态码：400 参数/上传/预检失败；401 未登录；404 不存在（含跨租户访问，不泄露存在性）；409 该租户已有训练在跑（「启动」按钮置灰）。 权限：所有 /api/skillopt/* 接口从 JWT 解析租户，任务/上传/产物全部按 tenant_id 隔离；菜单显隐由 role_permission_t 控制。

③ 状态机与轮询规则（前端唯一需要维护的状态）
idle 空闲→ 点启动（预检失败则留在表单页报错）→ running 运行中→ 自然结束 → finished 完成／点停止 → stopped 已停止／异常退出 → failed 失败
  • 监控页挂载时开始轮询 status + logs（各 2s，页面离开时清理定时器）；status.running=false 后再拉一次日志收尾，停止轮询。
  • 每个租户同时只跑一个训练（409 拦截）：任何页面进入时先查一次 status，若 running 则「启动训练」置灰、监控页直接续上（刷新浏览器不丢——任务记录在 PostgreSQL，日志用 offset=0 全量拉一次再增量）。
  • 「已中断/失败」的任务再次以相同配置启动，训练会从断点自动续训（SkillOpt 引擎行为，前端无需特殊处理，可在文案上提示）。
④ 联调清单（我们俩对接用）
  1. 后端起服务后给你 Swagger 地址（http://…:5016/docs），本地开发可在 next dev 里把 /api/skillopt 代理到它。

  3. 用例 B：不上传技能/数据直接启动 → 前端必填校验拦截；上传后选一个「不可用」的模型启动 → 预检 400 报错展示（本原型勾选「模拟预检失败」可预览）。
  4. 用例 C：上传技能 .md + 数据集（raw 与 zip 两种各测一次）→ 启动 → 监控页阶段/进度/日志滚动 → 停止 → 状态变「已停止」。
  5. 用例 D：同配置再启动 → 日志出现断点续训标记。
  6. 用例 E：上传含非法字段的 YAML → 400 逐条错误展示；合法 YAML → 启动生效。
  7. 用例 F：完成后结果页出现新 run，best_skill.md 可预览、可下载。
  8. 用例 G：运行中再点启动 → 40901 提示；刷新浏览器 → 监控页状态恢复。
