# 数据 Agent 平台：架构蓝图与 MVP 交付计划

> 完整版本（含分层图、排期泳道、风险表）见同目录 `dataagent-mvp-blueprint.html`。
> 内部文档。

面向公司数据部门的智能体平台：自然语言取数与元数据问答。本文给出平台的完整目标架构、
一个 4 人 20 工作日可交付的 MVP 精简架构、逐项功能对比、逐日任务规划与风险清单。

## 决策记录

| 决策项 | 结论 |
|---|---|
| 实现方式 | 自研，分两层落地：框架层（通用智能体底座）+ 应用层（数据业务）。编排底座依赖 LangGraph |
| 业务主线 | 取数问答 Text-to-SQL + 元数据/资产盘点问答 |
| 数据源 | MVP 打通 PostgreSQL + MySQL；StarRocks 进完整版 |
| 数据安全 | 只读账号 · 表白名单 50–200 张 · SELECT-only · 强制 LIMIT/超时/行数上限 |
| 元数据 | 无现成元数据平台，注释覆盖 ~80% → 自建表卡片，LLM 半自动生成 + 人工校对 |
| 知识库 | 调用公司现成向量库 API，不自建 RAG |
| 编排 | 单 Agent + Tools 循环（ReAct），按多 agent 骨架写 |
| 代码执行 | MVP 零沙箱，图表由前端 ECharts 渲染 |
| 模型 | 阿里云百炼，OpenAI 兼容 ModelProvider，默认 qwen-max |
| 合规 | 表结构与查询结果均可进 prompt |
| 前端 | Vue 自研；API 契约为平台标准的 thread/run/message/tool_call/artifact 五对象语义 |
| 认证授权 | 账号密码 + session；统一数据权限，role/allowed_roles 占位；全量 SQL 审计 |
| 存储 | Postgres 单库 + S3；不用 Redis、不用 MQ |
| 部署 | K8s replicas=1 + Recreate；重启后 running → interrupted 可重试 |
| 扩展点 | 只做工具注册表抽象；技能包/外部工具协议/渠道进完整版 |
| 记忆 | 仅会话内上下文；落 qa_samples 只写不读 |
| 验收基线 | 30–50 题黄金测试集，第 1 周建立，每日自动回归 |

## 七条架构原则

1. 框架层与应用层单向依赖，用 CI 测试强制。
2. 单一状态载体，禁止各中间件藏私有状态。
3. 中间件链：模型调用前的处理拆成有序可插拔段。
4. 工具多源装配，新增工具不改引擎。
5. 流式双通道：增量 + 周期性有界快照。
6. 配置分权：会导致代码加载的配置项只能由运维掌管。
7. 入口最小暴露：只有网关对外，由 CI 校验部署清单。

## 待确认假设

- **A1** 没有干系人明确要求「跑 Python 分析」→ 零沙箱写死，预留 3 人天 pandas 后处理预案。
- **A2** 能拿到历史 SQL 日志 + 业务方派 1 人配合 2–3 天。
- **A3** 架构负责人每周 4 天编码（3 人配置下 3 天不够用）。
- **A4** 算法同学未做过 LangGraph 与 SSE 流式工程，需 2 天上手期（已排进 D1–D2）。

## 分工（3 人）

| 角色 | 拥有什么 | 对外只暴露 | 不碰什么 |
|---|---|---|---|
| 算法（框架层） | ThreadState、agent 循环、StreamBridge、工具注册表、ModelProvider、提示词 | RunManager 方法、事件流、Tool 基类 | 工具业务实现、SQL、元数据、应用层 |
| 架构（应用层 + 数据） | 网关与路由、认证、审计、持久化、元数据与表卡片、SQL 校验与执行、四个数据工具、评测、部署 | REST + SSE（对前端）、四个工具实现（对框架层） | agent 循环内部、提示词内容 |
| 前端 | Vue 工作台全部页面与状态管理、ECharts 渲染 | — | 后端代码；只认 D3 冻结的协议 |

**三处接口 D3 必须定死**：SSE 事件全集（架构主笔）、Tool 基类约定（算法主笔）、RunManager 方法签名（共定）。

## Top 风险

1. **R1 准确率不达标** — D15 是决策日，应对为收窄白名单、补表卡片口径、few-shot 救场。
2. **R2 验收期待错配** — D4 必须让验收方在范围文档（含「零沙箱」）上签字。
3. **R3 拿不到黄金测试集** — 降级为每周试用会，但必须上报「本项目将没有客观准确率指标」。
4. **R4 跨人接口错配** — 3 人方案新增的头号工程风险。缓解：D3 三件套接口定死 + D7 做一次「假集成」，提前三天暴露语义分歧。
