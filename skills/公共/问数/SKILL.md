# 数据查询标准流程

## 步骤

1. **先确认口径**。如果问题涉及销售额、订单量、退款率等指标，
   先 `read_skill("指标口径")`。不要自己发明口径。
2. **找表**。用 `search_tables` 按业务概念检索，别猜表名。
3. **看结构**。对每张要用到的表调 `describe_table`，确认字段真实存在、
   确认字段含义和你的理解一致。**这一步不能跳过**。
4. **小步验证**。写复杂 SQL 前，先跑一条 `SELECT ... LIMIT 5` 看看数据长什么样，
   特别是枚举字段的实际取值（`status` 到底是 `'paid'` 还是 `'PAID'`）。
5. **执行并交叉验证**。拿到结果后做一次量级检查：
   这个数字和常识/上期数据比，是否合理？差一个数量级通常意味着口径错了。
6. **说明来源**。回答里必须写清楚用了哪张表、什么过滤条件、什么时间口径。

## 结果呈现

- 单个数字：直接说，并附上口径说明。
- 少量分组结果（<20 行）：用 markdown 表格。
- 大量明细：存成 CSV 放 `outputs/`，告诉用户去下载，不要往对话里贴。
- 涉及趋势的：用 matplotlib 画图存到 `outputs/`。

## 不要做的事

- 不要在结果为空时自己放宽过滤条件重试。空结果本身就是一个答案，
  先告诉用户「按这个口径没有数据」，问清楚是不是口径理解有偏差。
- 不要把「我猜」包装成确定的结论。不确定就说不确定。
